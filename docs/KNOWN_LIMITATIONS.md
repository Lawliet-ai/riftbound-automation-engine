## 一、仍挂起的规则口径（等待拍板，未单方面定稿）

这些在开发中"读不出唯一解"，被保留等待权利人/官方判断，引擎按当前实现运行：

- **§809 法盾费 × §355.14.b 分摊族**：分摊族的目标要等到"结算链上进行确认时"（§383.3）才确定，而费用在**打出时**算，实测**法盾费收 0**；两种读法都能自圆，未定。
- **§822 主阶段伏击落点**：§822.1.c 没写时机限制；按字面，雷恩加尔 `VEN-179` / `UNL-120` 在自己回合开环时也能伏击进有敌方单位的战场，而引擎**只在反应窗口**列伏击落点。两种处理未定。
- **§811 待命三处口径**：㈠ `UNL-139` 从待命打出时"选择一处战场"是否受 §811.1.d 锁；㈡ 待命战场已不受你控制时 §811.1.d.3 的落点；㈢ 法术对决开环里能否布置待命。
- **§372 两件**：单事件替换选序 `ReduceDeps.replacementOrder` 生产端未注入；以及 `SFD-171` 与"休眠的金币"的优先顺序（原条目描述已漂，待重写）。
- **§466.5.c**：真读不出唯一解，不自行决定。
- 规则口径 17+ 项仍在"待拍板/挂起待拍板"。

> 这些条目意味着：**不要据本快照宣称规则"全部正确"或与官方一致**。

## 三、多人规则边界与重连（按源）

- 引擎 `setupGameMulti`（`engine/src/game/setup.ts:93`）可装配多副牌组；`battlefieldCountFor` 对 2 人返回 2、其余返回 3（`setup.ts:78`）。
- 但**随附的联机服务与界面是按 2 座位房间写的**：内置牌组对局（`diana`/`teemo`/`lucian`）都是两人；`Room.join` 按 `state.players` 顺序填座。**未验证** 3 人以上的联机流程与多人规则边界。
- **CONCEDE 未支持多人**：`interactiveGame.ts:3177` 的 `CONCEDE` 在剩余玩家多于 1 人时直接 `return`，不改变任何状态。也就是说"某玩家认输后移除该玩家、其余玩家继承/继续"的多人流程**尚未实现**；因此"能装配多副牌组"不能当成完整的多人对局支持。
- 重连：只有 `/api/reclaim`（凭 token + 活跃窗口认回座位，`room.ts:199`）；**没有**完整的断线恢复/续局协议。房间在内存中，进程重启即全丢。

## 四、自动对局 ≠ 真人数据

末轮 51,200 局是**固定演示牌组配对**的自动对局（4 策略 × 4 种子段 × 3,200），不是覆盖任意卡池的对局，也不是真人实测。**真人参与数没有记录**，本文不编造。累计 111,200 只是重复回归运行次数，不是独立样本。

## 五、症状 → 原因 → 处理

| 症状 | 原因 | 处理 |
|---|---|---|
| 某层被动技能静默失灵 | 没调 `installProviders()` | 启动时先调 `installProviders()`，再用 `makeGameDeps` |
| 打出牌不扣费 | 用了 `DEMO_DEPS`（无费用表） | 真对局改用 `makeGameDeps(seed)` |
| 扩展/改接通路后，新路径打出的法术零伤害/效果为空 | 通道改动只接了一条 apply 路 | 检查手牌/待命/效果打出等多条路径是否都接上（参考 `interactiveGame.ts` 的 apply 分支） |
| 房间掷完骰后静默卡死 | `/api/roll` 的 `submitRoom` 没带 `build` 闭包 | 调 `RoomManager.submitRoom(..., build)`，选完先后手时建局 |
| 调度阶段某个座位反复提交或卡住 | `pending.player` 在双方交齐前恒为队首 | 用 `view.mulliganSubmitted` 判断自己是否已交，别等 `pending.player` |
| 洗牌/随机不可复现 | 混用了建局 RNG 与运行期 RNG | 建局用 `makeRng(seed)`；运行期由 `makeGameDeps(seed)` 内部那支负责 |
| 客户端能看到隐藏信息 | 把权威 `state` 发给了客户端 | 只发 `view(viewer)`（经 `project` 脱敏） |
| 新卡不出现在合法动作/不触发 | registry 未登记 | 在 `registry.ts` 登记 `PLAY_SPECS` / `TRIGGER_FACTORIES` / 费用表等 |
| 卡图或卡文空白 | 快照不含官方卡图与逐字卡文 | 预期现象；自备有权使用的资源（见 [DATA_AND_CARDS.md](DATA_AND_CARDS.md)） |
| 录像存不下来 | 初始局面链非空（闭包含闭包） | 从空链开局；录像依赖初始快照 + 动作序列 |
| 类型检查/测试通过但真对局出问题 | 测试绿不等于真规则全对 | 以真对局复现为准；新增行为测试钉住修复 |
